## App Store Connect traps — all form-level, all paid for

- **Screenshots**: the set in `docs/appstore/screenshots/` is 1320×2868, which
  is **6.9"**. ASC's **6.5"** slot demands 1242×2688 or 1284×2778 and rejects
  the 6.9" files with a bare "dimensions are wrong". A converted set lives in
  `docs/appstore/screenshots-6.5/` — scaled to 1284 wide and centre-cropped 6px
  top and bottom rather than stretched, because the aspect ratios genuinely
  differ (0.4603 vs 0.4622).
- **App Privacy has a separate PUBLISH step.** Answering every question leaves
  it a draft, and ASC keeps erroring "an Admin must provide information about
  the app's privacy practices" until you publish.
- **The Privacy Policy URL lives in App Privacy**, not on the version page.
  Support URL and Marketing URL *are* on the version page.
- **Copyright** format is year + rights holder, no © symbol, and must match the
  name the developer account is enrolled under.
- **"Do you or your third-party partners collect data?" → YES.** You collect
  email/phone/name/UGC/user-id; answering No would contradict
  `PrivacyInfo.xcprivacy`, which Apple cross-checks. Supabase is infrastructure,
  **not** a third-party partner — the only direct SPM dependency is
  `supabase-swift`, whose transitive deps are Apple's own plus pointfree
  utilities. There is no analytics, ad, tracking or crash SDK in the app.
- **Content Rights** must be answered **yes**: course data is OpenGolfAPI under
  ODbL, attributed in About, the description, and the privacy page.
- Sign in with Apple is **not** required — Guideline 4.8 only applies if you
  offer third-party login, and this app is email/password only.

## Costs as traction grows

Apple $99/yr, Supabase Pro $25/mo, domain ~$12/yr, Resend $0–20/mo. Everything
is flat **except photos**: the bucket is public, so egress is charged per
thumbnail *view*, not per upload. ~200–400 KB per photo after downscaling; Pro
includes 250 GB egress, then $0.09/GB. A few hundred golfers is ~$25/mo flat.
If photos take off, the lever is thumbnail caching or a smaller stored size.

## Traps already paid for — do not re-learn these

- **Rebuilding a SQL function**: always start from its LAST `create or replace`
  across all migrations, not where it was born. `leaderboard()` silently lost
  its blocked-user filter this way and shipped to production.
- **Adding a defaulted parameter** to an existing function creates an
  *overload*, not a replacement — `drop function` the old signature first, or
  one-arg calls fail with "is not unique".
- **Date columns must be returned as text** (`to_char(..., 'YYYY-MM-DD')`). The
  supabase-swift decoder only parses full ISO-8601 timestamps; a bare
  `"2026-08-05"` throws at runtime. `PlayDate` is the only place that
  reads/writes them.
- **`.listRowBackground` on a `List` does not propagate to its rows** — it must
  go on each `Section`.
- **Multiple `.sheet(isPresented:)` on one view is unreliable.** This is what
  made "Add photos" silently do nothing. Use one `.sheet(item:)` with an enum.
  (But note: two stacked sheets in `ProfileView` *do* work — verified by test.
  Don't rewrite on assumption.)
- **`supabase db reset` destroys anything not in `seed.sql`.** Check what's in
  the local DB first. Fixture accounts and their data now live in `seed.sql`
  precisely so a reset is reproducible.
- **Only ONE simulator may be booted** during a UI-test run. A second booted
  device fails most of the suite with no code cause, which reads exactly like a
  regression.
- **Reactions toggle**, so any UI test touching them must clean up after itself
  or the next run deletes what it then looks for.
- **Production DB writes are gated** — the user must run `supabase db push`
  themselves.
- **A simulator build from Xcode is DEBUG, and DEBUG points at localhost**
  (`Supa.swift:13`). Rebuilding the App Review demo account through the
  simulator therefore creates it on the *local* stack, not on hosted — the app
  signs in happily and the account looks fine, while the backend Apple actually
  reviews still has nothing. Use `scripts/seed_review_account.py`, which always
  talks to hosted. Only a Release build (or TestFlight) reaches hosted from a
  device.
